# 实例测试规范

## 术语

“实例（instance）”指一个可运行的 IDE 实例，包含 Theia 后端服务、前端页面，以及可选的 pi Agent 服务。实例测试验证这个实例能否启动、面板是否可用、AI 交互和终端交互是否符合预期。

## 测试层次

| 层次 | 目的 | 工具 |
|---|---|---|
| 本地实例冒烟测试 | 验证实例能启动、基础面板可用 | 浏览器、项目启动脚本 |
| 单元测试 | 验证后端与扩展中的纯逻辑 | Node.js 测试框架（如 Jest） |
| 集成测试 | 验证前后端通信与面板联动 | 浏览器自动化（如 Playwright） |
| 服务端实例验收 | 验证 Linux 环境下远程访问与运行稳定性 | WSL 或 Docker |

## 本地实例冒烟测试清单

1. 启动后端服务。
2. 打开 Web 前端。
3. 依次确认 editor、git、terminal、agent-chat、浏览器五个面板能打开。
4. 确认同一类别面板只有一个实例。
5. 确认面板之间能通过消息或事件通信。

## AI 交互测试

1. 在 agent-chat 中输入请求，确认文本能流式返回。
2. 让 AI 修改文件，确认改动以差异（diff）形式可见。
3. 让 AI 执行 bash，确认执行过程在 terminal 中可见。
4. 验证日志通知是回调式推送，不需要轮询。

## 浏览器面板测试

1. 准备一个本地 HTML 文件。
2. 让浏览器面板渲染该文件。
3. 验证简单的交互式脚本可以运行。
4. 验证 AI 输出到 HTML 的渲染协议可用。

## 自动化测试

- 单元测试文件放在与被测代码相邻的测试目录。
- 端到端测试用例放在 `e2e` 目录。
- 测试结果与报告放入 `test-results`、`playwright-report`，这些目录已忽略，不提交。

## 验收标准

一个实例只有同时满足以下条件才视为通过测试：

1. 实例在目标 Linux 环境中能稳定启动。
2. 五个基础面板可用，布局约束生效。
3. AI 对话、文件改动展示、终端执行展示可用。
4. 浏览器面板能渲染本地 HTML。
5. 自动化测试全部通过，关键路径有手工测试记录。
